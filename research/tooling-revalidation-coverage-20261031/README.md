# Packet verifier invocation census

`scripts/revalidate_all.py` runs each packet's `verify.py` with no
packet-specific arguments and records any non-zero exit as `fail`. A verifier
that declares `required=True` arguments therefore exits with an argparse usage
error (return code 2) before it reads a single byte of evidence, and the audit
reports that as an evidence failure.

At revision `6ac6f9b67` the audit reports 204 packets: 110 pass, 51 fail, 43
skip. This census separates the 51 failures by cause.

## Method

* Packet population: non-hidden directories under `research/`, restricted to
  directories that contain a tracked file, matching the audit's population on
  a clean checkout of this branch.
* Argument contract: a literal `required=True` in an `add_argument` call in
  the packet's `verify.py`. A computed requirement is recorded as unknown and
  never counted as invocable.
* Image inputs: a packet's `runtime/**/report*.json[.gz]` recording `images` or
  `image_sha256` as role-to-sha256. The distinct hashes are resolved against a
  sha256 index of every tracked `.so`, `.elf` and `.bin` file, including a
  single gzip layer.
* Output: `census.json` records every packet's result; `census.md` summarises
  it. Both are written by the command below and are byte-stable for the same
  revision.

## Result

| Measure | Packets |
| --- | --- |
| Research packets | 204 |
| With `verify.py` | 161 |
| Without `verify.py` | 43 |
| Requiring a command-line argument | 48 |
| Requiring `--images` | 46 |
| Requiring `--repo-root` | 2 |

Of the 46 packets that require `--images`, 37 record image hashes:

| Role | Recorded | Resolved in the branch | Unresolved | Not recorded |
| --- | --- | --- | --- | --- |
| original | 37 | 37 | 0 | 9 |
| candidate | 37 | 0 | 37 | 9 |

Every recorded original resolves to a retained capture. No recorded candidate
resolves to any tracked file in the repository: those packets retain the plan,
the receipts and the report, but not the image their verifier replays. The 9
remaining packets record no image hash at all, so their required input is not
identified by the packet either.

Two further packets (`pump-multihop-sell-fees-20261029`,
`pump-multihop-token-quote-20261029`) require `--repo-root`. The revalidator
passes `--repo` for a fixed four-packet allowlist and no argument to these two;
supplying the root exposes a separate, real failure: the maintained sources no
longer equal the sources the packet compiled.

## Reproduce

```bash
python3 research/tooling-revalidation-coverage-20261031/inventory.py \
  --repo . --tracked-only --output /tmp/census.json --markdown /tmp/census.md
python3 -B research/tooling-revalidation-coverage-20261031/test_census.py
```

At `6ac6f9b67` the command prints `total_packets: 204`,
`packets_requiring_images: 46`, and `image_roles` with `candidate.resolved: 0`;
the test file runs 12 tests.

## Limits

The census is static: it reports what a verifier declares, not what it would
do once invoked. A packet whose verifier writes an optional default still
counts as invocable by the audit even if that default is wrong. Image
resolution covers tracked ELF candidates only; an image stored under another
name, inside a non-tracked file, or generated by a build step would not be
found. This census makes no claim about the correctness of the evidence the
invocable 110 packets verify, and it changes no packet.

The 43 packets without a verifier are outside this measurement; they are
reported because the audit counts them as skipped, and a skip is not a failure.
